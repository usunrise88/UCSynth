### ✅ [B-01] Note-on и note-off в одном блоке → голос навсегда в SUSTAIN
- **Где:** `components/audio/src/env.cpp:30-35`; связано `voice.cpp:47-48`, `synth.cpp:100,139,152`
- **high** / correctness / **high** ✅ воспроизведено
- **Что:** `env_tick` строит стадии по фронту `gate` относительно `prev_gate`, а `prev_gate` обновляется только внутри `env_tick`. `voice_note_on` → `env_trigger` ставит `ENV_ATTACK`, не трогая `prev_gate`. Если оба события попали в один дренаж очереди, к первому тику `gate == prev_gate == false` — фронта нет, огибающая идёт ATTACK→DECAY→**SUSTAIN навсегда**.
- **Отказ:** `synth_note_on(60)` + `synth_note_off(60)` из одного дренажа (`audio.cpp:156` дренит очередь целиком; `comm.cpp:40-55` разбирает до 128 байт подряд — пара кадров из одного USB-пакета кладётся за микросекунды). Замер: `peak after 4s = 0.3500, active=1` вместо 0/0. Повторный note-off **не лечит** — `synth_note_off` фильтрует по `key_down`, который уже `false`. Перенажатие ноты берёт другой голос. В poly слот держится вечно (steal требует IDLE или RELEASE, а голос в SUSTAIN).

### ✅ [B-11] Фазовый аккумулятор растёт без границы при `inc > 1` → осциллятор уходит в тишину
- **Где:** `components/audio/src/voice.cpp:164-166`; корень — `voice.cpp:102` (`mod[MOD_DST_PITCH]*24.0f` без клампа)
- **medium** / numeric / **high** ✅ воспроизведено
- **Что:** заворот сделан одним вычитанием (`if (phase >= 1) phase -= 1`). При `inc > 1` фаза растёт со скоростью `inc − 1`. Дальше теряется точность float: при phase ≈ 1.7e7 ulp = 2, дробная часть залипает в 0; выше 2^31 конверсия `(int)phase` — UB. Достижимо, потому что PITCH нигде не клампится: 8 слотов × depth ±1 → **±192 полутона** плюс детюн ±24.
- **Отказ:** нота 127 + детюн +24 + MODWHEEL→PITCH depth 1 (f ≈ 200 кГц): `peak 0.4999` → через ~2 мин `peak = 0.0000, phase = 1.84e7`. Обычная C4 + 4 слота на PITCH (f ≈ 67 кГц) — тишина через ~15 мин. Слышимая частота при этом верна; ломается именно долгоживущая нота/дрон.

### ✅ [B-13] ISR USB-Serial-JTAG и I2C установлены на Core 0 — ядро, зарезервированное под аудио
- **Где:** `main/app_main.cpp:65,68`; `components/comm/src/comm.cpp:74`; `components/display/src/display.cpp:159`
- **medium** / concurrency + perf / **high**
- **Что:** ESP-IDF выделяет прерывание на том CPU, **который вызвал `esp_intr_alloc`**. `usb_serial_jtag_driver_install()` и `i2c_new_master_bus()` аллоцируют ISR прямо внутри себя, а зовутся из `app_main`, который `sdkconfig` пинит на CPU0 (`CONFIG_ESP_MAIN_TASK_AFFINITY_CPU0=y`). Задачи на Core 1 — правильно, но прерывания на Core 0.
- **Отказ:** GUI + OLED. Каждый кадр OLED — 1025 байт через non-DMA I2C с 32-байтным FIFO ≈ 32 прерывания на flush × ~18 flush/с ≈ **600 входов ISR/с на Core 0**, плюс каждый USB-пакет (SET 40 Гц, STAT 2 Гц, ACK, каждая строка `ESP_LOG`). Каждый вход вытесняет `audio_task` посреди блока, раздувая `cpu_permille` и `s_late_blocks`. ## Проверено и признано корректным

Чтобы следующий аудит не перепроверял. Всё ниже прочитано и признано верным.

**DSP:** ZDF/TPT SVF эквивалентен канонической форме Cytomic, `k = 1/Q ∈ [0.02,2]`, cutoff в [20, 0.45·sr] — `tanf` не взрывается. Freeverb: все 12 длин = тюнинг Jezar × 48000/44100, spread 25, `comb_tick`/`allpass_tick` совпадают с оригиналом, `fx_reverb_bufsize()` точно соответствует нарезке. Ping-pong delay даёт эхо d слева / 2d справа / 3d слева. Пул wavetable 4115 float × 4 формы, смещения сходятся, guard `t[L]=t[0]` корректен, `coef[1025]` не переполняется даже при sr = 96 кГц. `waveenv_tick`, `lfo_tick`, `voice_init`, `synth_init` — корректны. `double` в горячих путях нет (регресс D-008 не вернулся). Клампы `src < MOD_SRC_COUNT` / `dst < MOD_DST_COUNT` реально защищают от OOB.

**Прошивка:** сборка на пиннутом ESP-IDF v6.0.2 — чистая, ноль предупреждений, `ucsynth.bin` 238 КБ в 4 МБ `factory`. Все границы реестра проверяются (`id >= PARAM_COUNT`), `static_assert` связывает размер `kParams` с `PARAM_COUNT`, **ни один параметр не может выгнать DSP за диапазон из GUI**. `std::atomic<float> g_values[]` constant-initialized, lock-free, single-writer — корректно. `gfx.cpp` полностью bounds-safe (всё идёт через клампящий `fb_pixel`). Init-последовательность SSD1306 верна. На аудиопути нет ни `ESP_LOG`, ни `malloc`, ни `printf`, ни `vTaskDelay`, ни I2C, ни мьютексов; задача самотактируется на `i2s_channel_write`, IDLE0 живёт, TWDT доволен. Размеры стеков (замерены по ELF): audio ≈ 2.3 КБ из 6144, display ≈ 1 из 4096, comm ≈ 0.8 из 4096. Партиции влезают в 16 МБ.

**Протокол:** побайтово совпадают sync, LEN, алгоритм CRC (CCITT-FALSE 0x1021/0xFFFF, без reflect и xorout), покрытие CRC (`LEN+BODY`), порядок байт CRC (LE), максимум тела, таблица опкодов, раскладки VALUE/PARAM/LISTEND/STAT/ERR, кодирование f32 (IEEE-754 LE через `memcpy` — без нарушения strict aliasing и без невыровненного доступа). Границы `frame_decoder_t`, `tmp[1+255]`, `b[85]` в `protocol.cpp` — без переполнений. Go-декодер не алиасит переиспользуемый read-буфер; `d.buf` реально ограничен; `d.buf = d.buf[2:]` не может проскочить настоящий sync.

B-62, B-63: транспорт и переполнение канала тестами не запускаются вовсе). `GOOS=windows CGO_ENABLED=0 go build/vet ./...` — чисто; теги сборки `midi_windows.go`/`midi_other.go` корректны, API совпадает.
